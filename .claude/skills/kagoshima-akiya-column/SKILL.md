# 鹿児島空き家相談センター（tamarie.jp）コラム自動生成スキル

## 0. 最初にやること（毎回必須）

1. リポジトリ内の既存コラムをすべて洗い出す（ファイル名・スラッグ・カテゴリタグ・
   公開月を一覧化する）。実装がどこにあるか不明な場合は、まずリポジトリ構成を
   `ls` / `grep -r "column-"` などで確認し、コラム1本＝1ファイルの実体
   （.md / .mdx / .astro / .tsx など）とブログ一覧ページの実体を特定する。
2. 一覧ページ（/blog 相当）のカードデータも確認し、カテゴリタグの表記ゆれが
   ないかチェックする。
3. 直近12本のカテゴリ内訳を集計し、偏りがあれば新規3本で調整する
   （例: 「相続・手続き」が3本続いていたら今回は避ける）。
4. 画像ファイルの連番（col10, col11, col12...）の最新値を確認し、次の連番
   （col13, col14, col15...）を今回の3本に割り当てる。
5. 既存の col10-typhoon.jpg 等の画像ファイルが**リポジトリ内のどのディレクトリに
   実在するか**を `find` / `grep -r "col10-typhoon"` 等で特定する。このディレクトリ
   を今回・以降の画像格納先とする（パスを決め打ちしない。見つかった実際の場所に
   合わせる）。
6. 環境変数 `OPENAI_API_KEY` の有無を確認する（`[ -n "$OPENAI_API_KEY" ]` 等）。
   - **設定あり →** 「4. 画像生成」は自動モード（OpenAI API直接呼び出し）を使う
   - **設定なし →** 手動フォールバックモードに切り替える。その場合のみ
     手順5のディレクトリ直下に `column-images-inbox/`（無ければ新規作成）を
     用意し、そこを一時置き場として使う

**既存コラムと内容が重複するテーマは選ばない。** タイトル・見出し構成が
既存記事と本質的に同じにならないよう、必ず上記1で作った一覧と突き合わせる。

## 1. トピック選定

以下のカテゴリバンクから、直近と被らない3テーマを選ぶ。季節性がある
テーマは時期に合わせて優先度を上げる（例: 6-7月は台風・大雨対策、
11-1月は固定資産税の納付時期、2-3月は相続・確定申告関連）。

**既存カテゴリ（実績あり、継続的に使う）:**
防災・台風対策 / 空き家バンク・活用 / 防犯対策 / 固定資産税・リスク /
売却・管理 / 相続・手続き / リノベーション・活用 / 特定空き家・行政対応 /
売却・買取 / 解体・費用 / リスク・対処法

**新規開拓候補（ネタ切れ防止用のストック。使ったら上のバンクに昇格させる）:**
空き家の火災保険・地震保険 / 空き家×民泊活用 / 空き家×駐車場・トランクルーム
活用 / 空き家の境界確定・測量トラブル / 共有名義（共有持分）の空き家 /
空き家の名義変更・登記 / 離島・郡部の空き家事情 / 空き家インスペクション
（建物状況調査）/ シロアリ・害獣被害対策 / 空き家の水道・電気・ガス契約整理 /
空き家×太陽光・農地付き物件 / 空き家の解体前に確認すべき補助金制度 /
空き家を賃貸に出す際の原状回復・入居者トラブル / 空き家の生前整理・遺品整理 /
鹿児島市以外（霧島市・薩摩川内市・日置市など）のエリア別事情

各テーマにつき、想定検索キーワード（例:「鹿児島 空き家 火災保険」）を
1本ずつ明記し、記事タイトルとmeta-keywordsに自然に含める。

## 2. 記事の構成テンプレート

既存記事（column-typhoon, column-akiya-bank, column-security ほか）から
抽出した固定構成。**この構成を崩さない：**

```
[パンくず] TOP › コラム › {カテゴリ短縮名}

{カテゴリタグ}

# {タイトル（体言止め or 疑問形、20〜30字目安、｜で副題を繋ぐ）}

📅 {YYYY年M月}✍️ TAMARIE編集部⏱️ 約{N}分で読めます

[← コラム一覧に戻る] ![{画像alt: 何が写っているか説明的に}](col{N}-{slug}.jpg)

{リード文: 画像直下、記事の要点を1文で。太字は使わない}

{導入パラグラフ: 悩み・課題の提示。2〜3文}

## {H2見出し1}
{本文。重要語は**太字**で強調。2〜4パラグラフ}

## {H2見出し2}
{本文。必要に応じて表（| 項目 | 内容 |）やチェックリスト（📌 or ⚠️ or 🔍 絵文字
＋ - 箇条書き）を挿入}

## {H2見出し3〜5}
{本文。TAMARIEのサービスへの自然な言及を1箇所は入れる（「TAMARIEでは〜」）}

### {締めの小見出し。「〜、一度点検してみませんか？」等の問いかけ形}
{CTA前振り1文}

[✉️ 無料相談はこちら]

タマリエ（株式会社TAMARIE）は鹿児島の空き家相談の専門会社です。
© {年} 株式会社TAMARIE All Rights Reserved.
```

**meta情報も必ず生成する：**
- canonical: https://tamarie.jp/column-{slug}
- meta-description: 120〜160字、記事の要点＋TAMARIEへの誘導を含む
- meta-keywords: 「鹿児島 空き家 {主要キーワード}」を含む5個程度、カンマ区切り
- meta-og:title / meta-og:description: description/titleと同一or微調整
- meta-og:type: article

**文字数目安:** 本文2,000〜2,800字（⏱️表示の分数と整合させる、1分≒400字換算）

**トーン:** 専門家が丁寧に解説する口調。煽りすぎない。「〜かもしれません」
「〜が現実的です」など断定を避けつつ具体的。数字・表・チェックリストで
具体性を担保する。絵文字は見出し装飾（📌⚠️🔍✓）に限定し多用しない。

## 3. ファイル・スラッグ命名規則

- URLスラッグ: `column-{英語or ローマ字の短い識別子}`
  （例: column-fire-insurance, column-minpaku）既存と重複不可
- 画像ファイル名: `col{連番}-{スラッグと同じ識別子}.jpg`
- 3:2想定のヒーロー画像1枚のみ（本文中への挿入画像は現状使わない方針を踏襲）

## 4. 画像生成（OpenAI API による自動生成・gpt-image-1）

ChatGPTのアプリ画面は自動操作できないため、**OpenAIの画像生成API
（gpt-image-1）を直接呼び出す**ことで自動化する。`OPENAI_API_KEY`が
無い場合のみ、本セクション末尾の手動フォールバックに切り替える。

### プロンプトの組み立て方（自動・手動どちらの場合も共通）

プロンプト末尾には毎回以下の共通スタイル指定を付ける：

```
フォトリアリスティックな実写風景写真、ドキュメンタリー写真のような自然な質感、
イラスト・アニメ・CG調は避ける、彩度は抑えめで自然な色調、横長3:2構図、
テキストや透かしは入れない。
```

プロンプト本文を書く際のチェックリスト：
- [ ] 記事のテーマを、既存画像と被らない**具体的なシーン・瞬間**に落とし込んで
      いるか（「古い家」で終わらせず、動作・状況・時間帯まで指定）
- [ ] 人物を含める場合、正面から顔がはっきり分かる構図は避け、後ろ姿・横顔・
      斜め後ろなど「実在の取材写真に見えて誰かは特定できない」構図を明示指定
- [ ] 廃墟感を出すべきテーマ（放置リスク系）以外では「手入れされた住宅」
      「過度に荒れていない庭」を明示し、放置リスク記事との混同を防ぐ
- [ ] 台風・夜間・屋内など、記事ごとに異なる時間帯／天候／光源を意識的に
      散らし、3本並んだときに単調にならないようにする

### 自動モード：生成コマンド（1記事＝1回呼び出し）

事前に `OPENAI_API_KEY` が設定されていることを確認する
（未設定ならこのモードに入らず手動フォールバックへ。キーをコード内に
ハードコードしない）。

```bash
curl -s https://api.openai.com/v1/images/generations \
  -H "Authorization: Bearer $OPENAI_API_KEY" \
  -H "Content-Type: application/json" \
  -d '{
    "model": "gpt-image-1",
    "prompt": "'"${PROMPT_TEXT}"'",
    "size": "1536x1024",
    "n": 1
  }' | jq -r '.data[0].b64_json' | base64 --decode > "{格納先ディレクトリ}/col{N}-{slug}.jpg"
```

- `size: 1536x1024` は3:2の横長構図に一致する（既存記事のヒーロー画像の
  アスペクト比を踏襲）
- 生成した画像は、手順0-5で特定した既存画像の格納ディレクトリに直接保存する
  （手動ダウンロードのステップを挟まない）
- gpt-image-1はOrganization Verificationが必要な場合がある。API呼び出しが
  認証エラーになった場合は、その旨をそのままユーザーに伝える
  （platform.openai.comのSettings→Organization→Verificationで対応可能）
- API呼び出しが失敗した場合（認証エラー・レート制限・content policy
  violation等）は、エラー内容をそのままユーザーに提示し、リトライは
  最大1回まで。2回失敗したら止めてユーザーに判断を仰ぐ
- コストが発生する処理なので、1回の実行（3記事＝3回のAPI呼び出し）を
  超える追加生成（作り直し）は、必ずユーザーに確認してから行う。料金は
  変動するため、実行前に platform.openai.com の最新Pricingページで
  確認するようユーザーに促す

### 手動フォールバック（OPENAI_API_KEY未設定・API利用不可の場合のみ）

1. プロンプトをそのままコピペできる形でテキスト出力する
2. ユーザーがChatGPT UIで生成→ダウンロード→`column-images-inbox/`へ配置
3. ユーザーが「画像を格納して」と伝えたら、inbox内のファイルを
   col{N}-{slug}.jpg形式にリネームして正式なディレクトリへ移動し、
   本文ファイル内の画像パス・alt属性との紐づきを確認したうえでinboxを空にする
4. ファイル名だけで自動判定できない場合（複数候補がinboxにある等）は
   必ずユーザーに確認する。誤って別記事の画像を上書き・誤配置しないことを優先する
5. どちらのモード（自動／手動）で動いたかは、実行結果として毎回明示する

## 5. 一覧ページへの反映

新規3本を一覧ページのカードリストに追加する。既存カードのデータ構造
（カテゴリタグ、タイトル、日付、著者、リンク先）に完全に合わせる。
カテゴリタグの文言は本文側と一覧側で表記を統一する（例:
「防災・台風対策」で統一、「防災」「台風対策」のような揺れを作らない）。

## 6. 出力形式（1回の実行＝3本分をこの形でまとめて出す）

各記事ごとに：
1. コラム本文ファイル（実装形式に合わせて作成 or 既存ファイルへの追記・編集）
2. 一覧ページへの追加分（diffまたは追加ブロック）
3. 生成した画像ファイルのパス（自動モード）、または画像生成プロンプト
   （手動フォールバック時）
4. 想定検索キーワードと、狙いを1行で（ユーザー確認用）

最後に、今回選んだ3テーマが既存コラムと重複していないことの確認結果と、
画像生成が自動／手動どちらのモードで行われたかを一言添える。

## 7. 品質チェックリスト（出力前に必ず自己チェック）

- [ ] 既存記事とタイトル・見出し構成・結論が本質的に重複していない
- [ ] meta-descriptionが120〜160字に収まっている
- [ ] 主要キーワードがタイトル・見出し・meta-keywordsに自然に含まれている
- [ ] TAMARIEのサービスへの言及とCTAが記事内に存在する
- [ ] 数値・統計（固定資産税額など）を新たに主張する場合、既存記事の
      前提（評価額4,000万円の例など）と矛盾していないか、または
      「目安です」等の注記を付けているか
- [ ] 画像が他の記事と画（え）が被っていないか
- [ ] カテゴリタグの表記が本文・一覧ページで一致している

## 8. 週次実行に関する運用メモ

このスキル自体はコンテンツ生成ロジックであり、スケジューリング機構は
含まない。週1回・3本ずつ自動実行したい場合は、Claude Codeのヘッドレス
実行（`claude -p "このスキルに従って今週分のコラム3本を作成して" `等）を
cronやGitHub Actionsから呼び出す運用を別途組む。`OPENAI_API_KEY`は
実行環境の環境変数・シークレットとして渡し、リポジトリには含めない。
実行後は必ず人間によるレビュー（誤情報・法令に関する記述の確認、生成画像の
目視チェック）を挟んでから公開すること。
